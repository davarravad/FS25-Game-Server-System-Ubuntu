INSTALLATION & MAINTENANCE

Connect a node. Manage it here.

Ubuntu setup, signed software releases and administrator-controlled remote updates.

Prepare the main site first

The release maintainer creates the private release bucket, configures the public signing key, applies the database migration, deploys this site and publishes a signed release. Follow the complete setup and migration guide for commands and recovery instructions.

Keep GitHub public until every existing node has successfully updated from this site.

Install a new Ubuntu 24.04 node

  1. Sign in as an administrator and enroll a unique node under Access & nodes. Save its token.
  2. Run the two commands below on the Ubuntu server.
  3. Enter the node ID and hidden token. Verify the signing-key fingerprint with your maintainer, then select a published release.
  4. Finish the one-time Tunnel and Access setup, install your licensed game content and test a spare game.
sudo apt-get update && sudo apt-get install -y ca-certificates curl python3 openssl
curl --fail --show-error --silent --proto '=https' --tlsv1.2 https://farmservers.sargentweb.com/install.py -o /tmp/farmservers-install.py && sudo python3 /tmp/farmservers-install.py --install

The node generates unique passwords, keeps administrative ports on loopback and checks for approved updates over outgoing HTTPS. No GitHub credentials are installed.

Migrate an existing node

Apply the final reviewed GitHub bridge update, enroll the node and start its publisher. Download the bootstrap above, then use adoption instead of a fresh installation:

sudo python3 /tmp/farmservers-install.py --adopt /absolute/path/to/existing/node

Adoption preserves its directory, configuration and Compose project. Follow the migration checklist before making GitHub private.

Update from the dashboard

  1. The maintainer packages a reviewed commit with the offline signing key.
  2. An administrator uploads the signed JSON under Node software & setup.
  3. Select one pilot node and release, then choose Update selected node.
  4. Refresh update status. Verify telemetry and consoles after success, then update the remaining nodes individually.

Updates back up the panel database and configuration and rebuild control services. They do not restart game instances or update game binaries. Offline nodes retain queued jobs until reconnecting; cancel queued jobs if plans change.

Recovery

Check sudo journalctl -u farmservers-update.service -n 100. Root-only backups are under /var/backups/farmservers/JOB-ID. Normal apply failures restore previous source and control images; interrupted updates need inspection. Preserve SSH access and off-host game-save backups. The complete guide includes recovery and acceptance checks.
